# dsh-agent-vault

> npm 包名是 **dsh-agent-vault**（原 `dsh-agent-memory` 在 npm 上已被他人占用）。

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）用的智能体记忆与知识库插件。

每个智能体有一段**可继承的短记忆**；所有智能体共用**一个详细的共享知识库**；每个对话可以单独绑定一个智能体，因此同一时间可以有多个对话分别处于不同角色。

---

## 它解决什么

DSH 的会话本身是无状态的。跨任务时，你需要自己把上下文重新灌进去；而做完一件事之后，踩过的坑、验证过的命令、为什么这么选，通常散落在对话里，下次用不上。

这个插件补两块：

- **记忆**：智能体在任务完成或交接时，把结果压缩成一段很短的话（默认上限 4000 字）。这段记忆不自动生效——**由用户决定**把它读进哪个对话。
- **知识库**：详细经验（路径、命令、坑、决策理由）。**由智能体自己决定**什么时候查、查什么、何时补充。

两者权限刻意分开：模型没有任何"读记忆"的工具，只能写；知识库的读则只对模型开放，用户侧只能浏览和编辑。

## 功能

| 能力 | 说明 |
|---|---|
| 智能体管理 | 新建 / 改名 / 删除，互不影响 |
| 短记忆 | 每个智能体一份，上限可配，面板里直接编辑，改动留审计日志 |
| 共享知识库 | 所有智能体读写同一库，每条记录贡献者，支持搜索 / 标签 |
| 按对话绑定 | 新建对话时在下拉里选智能体；各对话互不干扰 |
| 记忆注入 | 只注入该对话绑定（或默认）智能体的记忆 |
| 记忆不自动读 | 面板里没有任何"注入"入口，只有绑定；模型侧也没有读记忆的工具 |
| 知识库自主查 | `agent_knowledge_search` / `read` / `write` 由模型自行决定调用 |
| 讨论室 | 可建多个房间；用户指定哪些智能体加入，成员可中途加入或退出；每条发言标注是哪个智能体说的 |
| 私有日志 | 每个智能体一份详细的日记式记录，**只有它自己能读写**，按需检索，不自动注入 |
| 接力（检查点） | 上下文到阈值时提醒模型先写记忆和日志，两件都完成后自动写下一份交棒检查点（`checkpoints/<agentId>.jsonl`）；可选额外导出 markdown；settle 后新会话自动继承绑定、审批策略与模型，面板「续会话」一键续到新会话；可开启「检查点后自动开启新对话」，并在新对话里自动发送一条「启动指令」 |
| 自动归档 | 续会话/新会话接管后，旧会话自动转为**归档**（只读、可查看、不能继续）；面板「对话」页签可取消归档、转**强归档**（侧栏隐藏、面板灰色）或转回归档 |
| 侧栏右键菜单 | 侧栏「智能体对话」里右键对话：打开 / 归档 / 转化为强归档 / 取消归档 / 在该智能体名下新建对话；Ctrl（⌘）点击切换选中、Shift 点击区间多选，右键作用于整个选中集合；右键智能体行可新建对话或收起/展开 |

## 安装

DSH 插件以 profile 包的形式安装。任选一种：

> **版本提示**：npm 的 `latest` 从 **2.0.0** 起指向 2.0（召回层、检查点页签、侧栏右键菜单）。仍在 1.3.3 上的，按 [从 1.3.x 升级到 2.0.0](docs/migrate-1.3-to-2.0.md) 走一遍即可，磁盘上只会多出 `checkpoints/` 与 `index/`。1.2.0 / 1.3.0 漏打包了 `archive.js`（`index.js` 却静态导入它），装完会报 `ERR_MODULE_NOT_FOUND`，不要用这两个版本。要从源码改代码，用目录或 `link:` 安装。

### 方式一：从目录安装

```bash
dsh plugin --profile <你的 profile> add dsh-agent-vault
```

也可以直接从目录装：

```bash
dsh plugin --profile <你的 profile> add /path/to/dsh-agent-vault
```

### 方式二：手工加到 patch 层

把仓库放到任意位置，然后确保 profile 的 `node_modules` 能解析到它（`pnpm add link:<路径>`），再在 profile 的 `cordis.patch.yml` 末追加：

```yaml
- insert:
    - id: agent-memory
      name: "dsh-agent-vault"
```

**装完必须完全退出并重开 DSH**，不要依赖热加载。

## 配置

配置写在插件条目上，全部可选：

```yaml
- insert:
    - id: agent-memory
      name: "dsh-agent-vault"
      config:
        memoryDir: "D:\\dsh\\agent-memory"   # 记忆与注册表根目录，默认 ~/.dsh/agent-memory
        knowledgeDir: "E:\\Agent-knowledge"  # 知识库目录，默认 <memoryDir>/knowledge
        memoryLimit: 4000                    # 记忆上限字数，500-20000
        entryLimit: 48000                    # 单条知识上限字数，2000-200000
```

知识库目录也可以直接在面板「设置」里改，立即生效（不迁移已有内容）。

## 数据布局

```
<memoryDir>/agents.json                 智能体注册表
<memoryDir>/settings.json               知识库目录、默认智能体、对话入索引、排序模式（recall.mode / 权重 / 余弦下限）
<memoryDir>/bindings.json               对话 → 智能体 绑定
<memoryDir>/memory/<agentId>.md         该智能体的记忆
<memoryDir>/memory/<agentId>.log.md     记忆写入审计（追加式）

<knowledgeDir>/<entryId>.md             共享知识库条目（front matter 带 agent 贡献者）

<memoryDir>/rooms/<roomId>/room.json     讨论室元数据（名称、成员）
<memoryDir>/rooms/<roomId>/messages.jsonl 讨论室发言（每行一条，带发言人）
<memoryDir>/journal/<agentId>.jsonl      私有日志·笔记（每行一条，只有该智能体可读）
<memoryDir>/checkpoints/<agentId>.jsonl   私有日志·检查点（2.0 起从这里读；旧文件首次访问时自动拆分）
<memoryDir>/index/state.json             召回索引的构建记录（builtAt / 各来源条数 / semantic 状态）
<memoryDir>/index/aliases.json           别名表（手写，{"别名": ["实体", …]}）
<memoryDir>/index/vectors.bin            语义向量（float32、L2 归一化，按 entries 顺序）
<memoryDir>/index/vectors.json           向量的元数据（{key, row, src, at, hash, chunk, chunks}）
<memoryDir>/index/access.json            引用/打开/曝光计数（2.0.0-beta.4 起，热度排序用）
<memoryDir>/models/<model>/              本地 embedding 模型（不进 npm 包，用 scripts/fetch-model.mjs 下载）
<memoryDir>/handoff.json                 接力配置（阈值、导出目录）
<memoryDir>/handoff-state.json           每会话的接力阶段
```

全部是普通 Markdown / JSON，可以直接用编辑器改，也可以纳入 git。

## 模型侧工具

| 工具 | 作用 |
|---|---|
| `agent_memory_save` | 写该智能体的短记忆（覆盖式） |
| `agent_knowledge_search` | 检索共享知识库；空查询列出最近条目 |
| `agent_knowledge_read` | 读一条完整内容 |
| `agent_knowledge_write` | 新增或按 `entry` 修订已有条目 |
| `agent_room` | `action`: `list` / `read` / `say` / `join` / `leave`，参与讨论室 |
| `agent_journal` | `action`: `list` / `search` / `read` / `write`，读写**自己的**私有日志 |
| `agent_recall` | 按关键词检索*可召回材料*：自己的日志笔记、自己的记忆审计、共享知识库、自己相关的会话原文；`mode` 选 `hybrid`（默认，词法 + 语义）或 `lexical` |
| `agent_alias` | 维护别名表：`list` / `set` / `delete`，让「说得出口但写不出来」叫法也能被检索到 |

工具通过调用会话的绑定解析智能体；显式传 `id` 时优先。`agent_journal` 与 `agent_recall` 永远只作用于调用方的智能体，**不接受其他智能体 id**，这就是隔离的实现方式。

`agent_recall` 也接受 `expand`（默认 1：一跳关联扩展，0：纯词法）与 `source` / `since` / `limit`；语义层见下节。

`agent_recall` 永远不返回检查点：检查点是权威状态（整段注入、旧的可能误导），只属于「读取」，不属于「检索」。检索结果走工具返回值而不是 system prompt，所以不会顶掉前缀缓存。排序规则（标题权重、覆盖率平方、30 天半衰期）见 [`docs/memory-recall-v2.md`](docs/memory-recall-v2.md)。

> **2.0.0**：召回层随 2.0 转正，契约冻结（工具参数、宿主 op、设置键、磁盘格式见 [`docs/memory-recall-v2.md`](docs/memory-recall-v2.md) §13），从 2.0 起破坏性变更只发生在 3.0。磁盘上只多出 `checkpoints/` 与 `index/` 两个目录，旧数据首次访问时自动拆分，不会写坏。**从 2.0 降回 1.3.x 之前**，先把 `checkpoints/<agentId>.jsonl` 的行并回 `journal/<agentId>.jsonl`（1.3 只读后者），否则旧版会看不到检查点；完整迁移与回退步骤见 [从 1.3.x 升级到 2.0.0](docs/migrate-1.3-to-2.0.md)。

## 接力（交棒检查点）

长时间任务会让单个会话堆到窗口边缘，越后面越贵、越容易复发早期已经修好的问题。接力做的事很简单：**在还来得及的时候，把这次工作沉淀成记忆和日志**。

| 阶段 | 发生什么 |
|---|---|
| watching | 每步进入前用 `ctx.tokenMeter.measure(session).totalTokens` 量压力，低于阈值什么都不做 |
| requested | 超过阈值：在该步的系统提示里插入一条交接提醒，要求模型先用 `agent_memory_save` 写记忆、再用 `agent_journal` 写一条详细日志 |
| ready | 检测到记忆的 `memoryUpdatedAt` 与最近一条普通日志都**晚于这次提醒** → 生成检查点 |
| settled | 检查点写入 `checkpoints/<agentId>.jsonl`（`kind: "checkpoint"`），本会话继续用，不再重复提醒 |

要点：

- **检查点属于该智能体的日志域**，不是工作区里的文件：`2.0` 起物理上单独存 `checkpoints/<agentId>.jsonl`（读取时与笔记合并，面板「检查点」页签单列）。它天然属于该智能体、天然隔离、天然能用 `agent_journal` 找回来。
- 记忆或日志掉回阈值 90% 以下（例如手动压缩过），这次请求会被清掉，允许下次重新触发。
- **提醒不换会话、不打断**：它只是在那一步的系统提示里多一段话，模型照常继续手上的工作。

### 阈值

只有一个 `triggerTokens`，默认 **300000**，是**绝对值、不按窗口自适应**。

| 窗口 | 建议阈值 |
|---|---|
| 256K（官方默认） | 180000 |
| 512K 及以上 | 300000–350000 |

窗口越小越要往下调，否则永远不触发，看起来像插件没工作。

### 配置

面板「接力」页签可改，也可以直接写 `<memoryDir>/handoff.json`：

```json
{
  "enabled": true,
  "triggerTokens": 300000,
  "remindEverySteps": 2,
  "exportDir": "",
  "autoSwitch": false,
  "startupPrompt": "这是交接后的新会话（上下文已重置）。先读你最近的日志和交棒检查点（agent_journal），再搜共享知识库里的相关经验，确认上次的进度后继续完成工作；结束前更新记忆和日志。"
}
```

`remindEverySteps` 控制提醒频率：超阈值后**每隔这么多步**才重复一次（默认 2）。第一次触发总会提醒，之后按这个间隔降噪；记忆和日志一落盘就彻底停止。提醒文本只写阈值、不写实时 token 数——它是一段 system prompt，文字一变后面全部消息都要重付缓存。`exportDir` 留空时就只写日志；填了会额外落一份 markdown（`checkpoint-<会话短 id>-<时间>.md`），方便用编辑器看或给别的工具读。`startupPrompt` 是自动切换后发给新会话的第一条消息，留空则只打开对话、不发消息（上限 2000 字）。

### 重置

「接力」页签的会话列表里，处于等待沉淀或已生成检查点的会话那一行会有「重置」。它只清掉该会话的阶段记录，让它重新从 `watching` 开始；已经写进日志的检查点**不会删除**。适合手动压缩过上下文、或者想在同一会话里再走一轮的时候。

检查点落盘后会记一个 30 分钟内有效的「下一会话」意图：在这个目录里新建的会话会自动绑定同一智能体，并继承审批策略、模型与 Agent preset（`resume`、子智能体和已绑定的会话不会误消费）。面板的「续会话」按钮把意图刷新 + 新建会话合成一步，并让新会话落在源会话所在的工作区、沿用源会话的模式。开启「检查点后自动开启新对话」后，客户端在回合结束、会话空闲时自动完成这套切换，旧会话自动归档；切换前会把「启动指令」写进交棒意图，新会话继承完成后由主机自动发送，作为它的第一条消息（手动「续会话」不发送）。API 事实与实现细节见 [docs/handoff-v2.md](docs/handoff-v2.md)。

## 面板

侧栏出现「智能体」图标，打开后：

- 左侧：顶部可在「智能体 / 讨论室」之间切换
- 智能体视图：列表显示记忆字数、贡献条数、被几个对话使用；右侧八个页签：记忆 / 回忆 / 对话 / 共享知识库 / 日志 / 检查点 / 接力 / 设置
- 对话页签：按智能体收拢它的对话（标题、工作区、时间、运行状态），可「打开」「解绑」；顶部可选工作区并「切换过去」或「新建对话」（新建的会话自动绑定该智能体）
- 讨论室视图：新建房间、点成员名字加入或移出、消息流、直接发言（Enter 发送）
- 检查点页签：按时间倒序列出这个智能体的交棒检查点（标题 / 摘要 / id / 时间），点开看全文与元信息（触发 token 数、阈值、所属会话），可「复制全文」。只读——检查点是权威状态，不从这里新建或删除，召回索引也不收录它
- 记忆页底部列出正在使用它的对话（显示**对话标题 + 短 id**），可一键解除绑定

已绑定智能体的对话会从左侧工作区列表里隐藏（客户端展示层过滤，不改会话数据，搜索仍可命中）。设置页可以关掉这个隐藏行为。工作区上方还有一块「智能体对话」区，按智能体分组列出这些对话，点一下就能打开。细节与限制见 [docs/sessions-and-workspaces.md](docs/sessions-and-workspaces.md)。

新建对话时，新会话那一行右侧会出现「智能体」下拉。

讨论室的发言由**用户驱动**：在某个已绑定智能体的对话里让它「去讨论室说点什么」，它会用 `agent_room` 读上下文并发言；也可以由你直接在面板里发言。插件不做自动轮流发言。

### 窄屏（手机）布局（2.0.2-beta.1）

面板原本是「264px 记忆库栏 + 主栏」的两栏结构。窗口一窄，主栏只剩几十像素，八个页签里靠右的几个会被裁掉——**既看不到也点不到**。2.0.2-beta.0 起，视口窄于 720px 时：

- 左侧记忆库栏变成**顶部横条**，记忆库是一个个胶囊，左右滑动切换（列表长了也不会把面板撑宽）；2.0.2-beta.1 起横条底部有一条**常驻的细滑块**（6px，悬停变亮），滑到哪、还有多少一目了然，不再是「藏起来猜得到」；
- 八个页签排成 **4 列 × 2 行**，全部可见、可点，不再依赖横向滚动或下拉；
- 头部、页签、正文的内边距从 26px 收到 12px，把宽度让给内容；讨论室的成员条、消息流、输入区同步收窄。

桌面宽度下布局完全不变（没有改动任何桌面端规则）。截图见 [docs/images/narrow-panel.png](docs/images/narrow-panel.png)。

## 侧栏右键菜单

侧栏「智能体对话」段（vault 自建的列表）支持右键：

| 位置 | 菜单 |
|---|---|
| 对话行 | 打开 / 归档 / 转化为强归档 / 取消归档 / 在「该智能体」名下创建新对话 |
| 智能体行 | 在它名下创建新对话 / 收起或展开它 |

- **多选**：Ctrl（macOS ⌘）点击切换单个对话的选中；Shift 点击在**同一智能体**内从锚点扩选。选中的行有底色，右键点了已选行时保留整个选区，否则选区重置为光标下的那一行。菜单头会显示「已选 N 个对话」。
- **动作落在整个选区上**：归档 / 强归档 / 取消归档对每个选中对话并发调用 `archive.set`，全部成功才提示成功，任一失败会在底部弹条里给出错误。
- 菜单项按选区当前状态禁用（都已归档就不能再归档；没有已归档的就不能取消归档；都已强归档就不能再转强归档）。
- 键盘：打开后方向键上下移动，Esc 或点击别处关闭。
- **在智能体名下创建新对话**：取该智能体最近一个已绑定对话的工作区，调用 `agent.newSession` 新建会话并立即绑定，然后切过去；没有历史对话时会话落在默认工作区。它不继承审批策略（那是「续会话」/ 交接的语义），需要继承时用面板的「续会话」。

## 回忆（2.0）

「回忆」页签是召回层的前端：按关键词检索**当前智能体**的日志笔记、它的记忆审计记录，以及共享知识库。

- 输入关键词回车或点「检索」，可先用下拉限定来源（日志 / 记忆 / 知识库）、用日期框只保留该日之后的内容；结果按 `标题权重 6 / 标签 4 / 正文 40 + 覆盖率平方 + 30 天半衰期` 排序，每条显示来源徽标、时间和得分。
- 点一条结果展开**全文**（面板里的展开视图，不影响任何索引状态）；再点收起。
- 索引状态卡片显示条目总数、构建时间与各来源条数。「重建索引」走 `memory.reindex`，重建后卡片立即刷新。
- 面板检索**只在索引里查**：不进 system prompt，不改缓存前缀，也不消耗额外 token。检查点不在索引里——它是权威状态，整段注入，永不被检索。
- 同样的能力模型侧用 `agent_recall` 工具发起，两者命中同一套索引。

### 关联扩展（2.0.0-alpha.3）

词汇命中之后，再做**一跳**扩展：沿三类边把字面不像、但其实相关的条目补在结果尾部。

- `ref`（权 0.9）：正文里写了另一条的 id（`j-xxxx`、知识库条目 id）；
- `entity`（≤ 0.6）：共享至少一个实体，实体按形状自动抽取（路径、`agent-xxxx`、`j-xxxx`、文件名、带点的 op 名、带连字符的包/仓库名），并被文档频率衰减——被半数条目重复的「agent-memory」这类词连不出东西；
- `session`（0.5）：同一 `sessionId` 的两条日志。

扩展项在面板里带「关联·实体 / 关联·引用」徽标，展开可看「关联自 X」；模型侧用 `agent_recall` 时，扩展项带 `via` 与 `why: {hub, edge, weight}`。想关掉对照基线就传 `expand: 0`。

别名表在 `index/aliases.json`（`memory.reindex` 会建一个空的），三个地方都能改：直接编辑文件、面板「回忆」页签的「关联别名」卡片、或模型侧的 `agent_alias` 工具。

```json
{ "vault 插件": ["dsh-agent-vault"], "小鲸鱼": ["dsh-whale-widget"] }
```

命中的条目以「关联·别名」出现——中文检索里加一行别名，比调边权划算得多。写进去立即生效（按文件 mtime 判脏，不需要 `memory.reindex`）；目标列表给空数组等于删除这个键。

op 侧对应 `memory.aliases`（读表）与 `memory.alias {key, targets}`（写；`remove: true` 删）。别名是全局的，不按智能体隔离——它描述的是「词与词的关系」，不是谁的经验。

#### 实测口径

真库 14 条人工标注查询：`expand:0` 与 `expand:1` 的 top-1 都是 92.9%、top-3 100%、MRR 0.952，单查询扩展不超过 2 条。同质语料上图扩展是「补尾不抢位」，收益要等字面完全不同、实体相同的样本出现才看得出来。

### 对话入索引（2.0.0-alpha.4）

前面三节检索的都是「智能体自己写下来的东西」。真正稀缺的信息常常只有原始对话里有，所以 `2.0.0-alpha.4` 把会话原文也接进来，来源标记为 `session`：

- **只读本智能体相关的会话**：它接力（handoff）过的会话，或通过绑定声明归属它的会话。别人的会话一条都不碰，这是按契约而不是按目录猜的。
- **只取 `user` 与 `assistant` 的文本**：工具返回值、推理过程、附件一律不入库，所以密码即使出现在工具输出里也进不来。
- **打码**：`sk-` 开头的密钥、`Bearer <token>`、`api_key=…`、GitHub `ghp_`/`github_pat_` token 在入库前替换成占位符。
- **体积上限**：每个会话最多 12000 字符（从头累加，超出的尾段丢弃），避免一次长会话挤爆索引；文件大小变化（会话仍是追加写）会让该会话重建。
- **格式**：`~/.dsh/sessions/<workspace>/session-<uuid>/session*.jsonl.zstd` 是 zstd 帧格式，插件自带一个只用 `node:zlib` 的最小帧解析器（`zstd-frames.mjs`，约 70 行），不引入原生依赖。
- **开关**：面板「设置」里的「对话入索引」；关掉后检索不再返回 `session` 来源的条目（索引缓存里已有的也不会被查询）。改动记录在 `settings.json`，彻底生效建议重启宿主。

代价是每次重建索引要读一遍相关会话文件（真库首轮约 1–2 秒，之后只对文件大小变化的会话重建）。如果只想看笔记和知识库，把开关关掉即可。

### 命中片段与逐会话取舍（2.0.0-alpha.5）

- **预览围绕命中词，而不是正文开头**：长对话的头几行通常是「继续」或一句寒暄，按开头截 160 字等于什么都没说。`rank.js` 的 `snippet()` 会在正文里找命中词最密集的 160 字窗口，两侧加省略号；一个词都没命中时才退回开头。
- **逐会话勾选**：「回忆」页签下新增「对话来源」卡片，列出本智能体有权读的每个会话（标题、时间、入库字符数）。取消勾选后该会话立刻退出索引（检索不到，`memory.reindex` 也不再计入），但「回到对话」照常可用。取舍记在 `settings.json` 的 `transcriptExclude` 里，与全局开关并存。
- 会话列表与勾选走 `memory.sessions` / `memory.transcript` 两个 op，`test-host.mjs` 覆盖了「未知会话被拒」与「没有会话时返回空列表」。

### 命中定位到具体消息（2.0.0-alpha.6）

会话来源的一行结果背后是一整段对话，只看预览往往判断不出「这话到底谁说的、什么时候说的」。`2.0.0-alpha.6` 把「命中的是哪一条」也带出来了：

- **索引时保留消息边界**：`transcripts.js` 不再只拼一整段文本，而是同时留下 `{seq, role, at, text}` 的消息列表；超出 12000 字预算时按「留头 + 留尾、丢中间」裁剪，消息列表与正文用同一份子集，不会出现「预览里有、点进去没有」。
- **结果带 `hit`**：`session` 来源的一行会多一个 `hit: {seq, role, at, text}`，指向词法得分最高的那条消息（`memory.open` 返回的条目也仍是整段，两者互补）。
- **面板**：结果行下方多一行「命中消息 #12 · 助手 · …」；展开后显示该条消息全文，并给一个「复制该条」按钮（走 `memory.message`），方便拿去别处搜。
- **不能自动滚动**：宿主的 `uiWorkspace.openSession` 只接受会话 id，没有消息锚点，所以「跳到第 N 条」做不到。能做到的是精确到消息 + 复制原文，「回到对话」仍然只回到会话。

### 日志命中也能回到对话（2.0.0-alpha.7）

记忆日志（`memory/<agentId>.log.md`）原来是纯文本审计，条目没有会话键，所以日志命中只能看不能跳。`2.0.0-alpha.7` 起：

- **写入时带上会话**：`agent_memory_save` 在标题行末尾追加 `[session: session-…]`。面板手写的记忆写 `panel`，没有会话可记就不加——旧日志原样保留，不用迁移。
- **解析时拆出来**：日志条目多一个 `sessionId`，`memory.open` 也会返回它，于是面板的「回到对话」对日志命中同样可用。
- 标题不会因此变丑：后缀在解析时被剥掉，`title` 还是人写的那句话。

### 语义检索（2.0.0-alpha.8）

词法检索的盲区是「换个说法就找不到」：笔记里写「自动弱归档」，查询说「会话怎么被收起来」，没有一个字重合。`2.0.0-alpha.8` 在**日志层**（journal + 记忆日志）上叠加本地语义向量：

- **模型本地、离线**：BGE-small-zh-v1.5 的 int8 ONNX（24 MB，512 维），走 `onnxruntime-node`（N-API，Electron ABI 稳定）。模型不进 npm 包，用 `node scripts/fetch-model.mjs` 下载（逐文件校验 size 与 sha256，按 hf-mirror → huggingface 顺序，可重跑续传）。分词是自写的 BERT WordPiece（`vocab.txt` 驱动），不引 `transformers.js`。
- **只嵌日志层**：检查点与 4K 短记忆是权威状态、整段注入提示词，嵌了反而可能把陈旧版本当检索结果；对话原文太大且未脱敏，仍走词法。向量存 `index/vectors.bin`（float32、L2 归一化）+ `index/vectors.json`（`{key, src, at, hash}`），**按内容 hash 判脏**——日志是追加写，按 mtime 会每次保存都全量重嵌。
- **融合用 RRF，不用加权和**：先按 `0.6×归一化词法 + 0.4×余弦` 实现，改写查询集只有 33.3%（vs 纯词法 25%）；原因是量纲——词法最大项恒被归一化成 1.0（占 0.6），余弦常年在 0.5–0.65（只占 0.2–0.26），任何有词法命中的条目都压住只靠语义的正确条目。改成倒数排名融合（`0.6/(20+lexRank) + 0.4/(20+semRank)`）后同一集合 top-1 41.7%。
- **余弦下限 0.45**：低于它的条目没有语义名次（不按相似度硬塞进来）；语义命中带 `via:"semantic"`，面板显示「语义」徽标，且**不作为图扩展的种子**（共现边与语义空间是两套结构，混用噪声相乘）。这个值是量出来的，不是拍的：见下面的「参数」一节。
- **`mode` 参数**：`agent_recall` 与 `memory.recall` 都收 `mode: "hybrid" | "lexical"`，默认 `hybrid`；`lexical` 是回归开关，词法基线（14 条词面可对的查询）必须保持 top-1 92.9% / MRR 0.952。
- **失败就退回词法**：模型缺失、ORT 加载失败、单次嵌入超时都只让这一次检索走词法，`memory.model {action:"status"}` 会报出原因；插件启动 4 秒后后台预热（`timer.unref()`），不阻塞启动。
- **实测**：15 条与目标笔记没有字面重叠的改写查询，词法 top-1 0.0% / MRR 0.180（1 ms）→ hybrid 13.3% / 0.286（22 ms，预热后）；词法基线（14 条词面可对的查询）在 hybrid 下反而 100%（语义把唯一失手的那条翻到了第一）。脚本是 `eval/recall-paraphrase.mjs`，逐条打印排名变化与语义独有命中，可复现。完整设计与取舍见 [docs/embedding-local.md](docs/embedding-local.md)。



### 语义索引卡片与排序开关（2.0.0-alpha.10）

「回忆」页签里，索引状态卡片下方多了一张**语义索引**卡片，把 alpha.8 的本地向量层从「只能看工具返回」变成可操作：

- **状态**：模型是否就绪（模型名 + 维度）、已建向量的条数、构建时间；模型缺失或 ORT 加载失败时直接显示原因（`model-missing` 等），并给出下载命令。
- **准备 / 同步向量**：一键走 `memory.model {action:"prepare"}`——加载模型（预热 150 ms）并按内容 hash 增量同步 `index/vectors.bin`。有新笔记后点「同步向量」即可，不用重建整个索引；模型不可用时按钮禁用。
- **排序开关**：`混合` / `仅关键词` 两个互斥按钮，写进 `settings.json` 的 `recall.mode`（经 `recall.save`），重启后仍保留。`仅关键词` 是回归开关：命中结果与 alpha.7 一致，且完全不加载模型。
- 排序模式对面板检索与模型侧 `agent_recall` 同时生效；单次调用仍可用 `mode` 参数覆盖。`settings.json` 里的 `recall.lexicalWeight` / `semanticWeight` / `minCosine` / `rrfK` 也可手工调，面板只暴露最常用的那个开关。

### 参数是量出来的（2.0.0-alpha.12）

融合参数（0.6/0.4、RRF `k`、余弦下限）原本是手定的：只有一份查询集，没有可以扫的工具。alpha.11 做了第一次参数化，但用的是「点估计比大小」——45 条查询上 MRR 的 95% 区间宽约 ±0.13，那个方法其实分不出参数好坏。alpha.12 重做：

- **用例只有一个来源**：`eval/cases.mjs` 同时给三个脚本用。两个族分开——`lexical`（14 条，与目标笔记共享词汇）和 `paraphrase`（**45 条，覆盖 24 条笔记**，几乎无字面重叠）。只有一个脚本里存的用例才会漂移。
- **改写用例先过体检**：`eval/check-cases.mjs` 打印每条查询在纯词法下的真实名次。词法已经排第一的用例量不出语义收益，移入 `DROPPED_CASES` 留档（累计剔掉 18 条）。
- **顺序轴，不是叉积**：`eval/recall-grid.mjs` 一次只动一个轴（权重 → `k` → 下限），每个候选都在当前选择上测，16 组配置代替 150 组，全跑约 10 秒。
- **配对 + 按笔记聚类**：候选与默认值的差值用自助法（4000 次、种子固定）给出 95% 区间，**区间含 0 就不改动默认值**。重采样按笔记分组而不是按查询：45 条查询只是 24 条笔记的 1–3 种说法，当独立样本会把区间算窄。结论里「no evidence to move」是一个正当结论。
- **余弦下限是硬边界，不是自由参数**：6 条无关查询（「给我讲个笑话」）把下限设为 0 时，全库最高余弦 **0.361**、中位 0.314；任何 ≤ 它的下限等于在每条无关查询上都放垃圾进来。所以候选只在 0.40 以上取，再交给配对区间判定。
- **词法路径不变性**：同一脚本把词法族在 `mode:"lexical"` 下跨 `k` 重跑，断言排名逐条一致——参数不许渗进词法路径。
- **顺带测了一个直觉并否掉了**：只嵌「标题 + 前 240 字」，纯语义排名更好（MRR 0.358 → 0.438），但对无关查询的余弦也一起抬高，下限被迫升到 0.45，端到端反而掉到 0.256。结论：整篇嵌，长笔记更具体（`vectors.js` 里留了注释）。

实测结果（真库 `demo-agent`，45 条改写 / 24 条笔记）：

| 轴 | 各候选与默认值的差值（95% 区间） | 决定 |
|---|---|---|
| 权重 | 0.4/0.6 +0.007 [0.000, 0.019]；0.5/0.5 +0.001 [-0.010, 0.013]；0.7/0.3 0.000；0.8/0.2 -0.010 [-0.039, 0.009] | 全部不可区分，**保留 0.6/0.4** |
| RRF `k` | 5 / 10 / 40 / 60 全部 Δ0.000 | **保留 20**（`k` 在这套打分里几乎不起作用） |
| 余弦下限 | 0.40 +0.006 [-0.047, 0.056]；0.50 -0.035 [-0.105, 0.025]；0.60 **-0.088 [-0.189, -0.003] 显著更差** | **保留 0.45** |

两件要说清楚的事：

1. **alpha.11 把下限从 0.45 改到 0.40 是没有证据的**（Δ+0.006、区间跨 0），alpha.12 改回 0.45。这是一次自我纠正，不是新发现。
2. **这套评测的灵敏度是 ±0.128 MRR**（45 条查询 / 24 条笔记），比它小的差异在这里测不出来。任何「参数微调带来 +0.01」的说法都不要当真。

结论：**参数已经调不动了**，而且这次是能说清楚的「调不动」。改写族 hybrid top-1 13.3%（6/45）、MRR 0.247，卡住它的是检索质量本身——纯语义排名里目标能排第一的只有 4/15，中位名次 6/25。下一步的收益在「换更强模型 / 分块 / 标题加权」，不在参数。

### 分块嵌入（2.0.0-alpha.13）

编码器只读 512 token，而本库笔记的中位数是 **654 token、28 条里 22 条超限**（`eval/token-check.mjs`）——整条嵌入等于把长笔记的尾部丢掉，而查询问的往往正是尾部那个细节（5,085 个 token 从未进过编码器）。

- **一条笔记对应多行向量**：按约 420 字切窗口（重叠 60 字，尽量落在句末），每段前面重复标题，`index/vectors.json` 升级到 v2（`row: "key#chunk"`、`chunks` 记段数），旧布局读到即作废重建。
- **相似度取各段最大值**，不取平均：一条笔记通常只讲一件事，平均会让别的段落冲淡真正对上的那一段。
- **A/B 结论（`eval/chunk-variants.mjs`，45 条改写 / 14 条词法）**：改写族 MRR 0.247 → 0.253（+0.006 [-0.066, +0.088]），260 字版本 0.266（+0.019 [-0.078, +0.115]）——**两个区间都跨 0**，所以不宣称提升；词法族 100% 不动；无关查询的噪声峰值 0.407 → 0.424，仍在 0.45 下限内。
- 上线的理由是正确性而不是分数：尾部信息重新可见，且没有任何一族回退。260 字窗口行数多 70% 且噪声更靠近下限，故取 420 字；`chunkChars: 0` 可复现 alpha.12。

### 标题加权与知识库语义：两个负结果（2.0.0-beta.2）

两件事都量过，都不上线，但旋钮和证据留下。

- **标题加权（`recall.titleWeight`，默认 0）。** 诊断脚本 `eval/title-vs-body.mjs`：词法族 14 条查询对标题的余弦确实系统性更高（0.689 vs 0.592，14/14 条），但改写族 45 条反过来（-0.041，只有 10/45 条标题更高）。改成「标题单独一行向量、与正文按权重混合」接进真实管线后，改写族 hybrid 变差：w=0 时 13.3% / MRR 0.281，w=0.15 是 11.1% / 0.280，w=0.25 是 8.9% / 0.251。原因是词法路径本来就给标题 6:1 的权重，再往语义列里塞一次标题等于双计，而 RRF 融合后单路语义的收益被稀释掉了——**标题的好处已经通过词法前排拿到了**。旋钮保留（`recall.titleWeight`，夹在 0–0.5），只有 >0 时才真的物化标题行，改它会触发一次重建。
- **知识库语义（`vectors.js` 的 `VECTOR_SOURCES` 不含 `knowledge`）。** 25 条共享条目、14 条改写查询（`eval/knowledge-eval.mjs`）：lexical 与 hybrid 都是 top-1 78.6% / top-3 92.9% / MRR 0.857，名次互换两条（修好 2 条、弄坏 2 条），净收益为零；更要命的是 6 条无关问题的余弦峰值 **0.471 > 0.45 下限**，接上就是每个无关查询都漏知识条目。所以知识库继续走词法（它的标题本身就是强信号），评测脚本留着，换模型或换下限口径时可以直接复跑。

### 写入时的绝对日期（2.0.0-beta.3）

记忆条目自带 `at` 时间戳，但**正文里的「今天」没有任何东西可以还原**：读它的人可能在面板里、也可能是一个月后的另一个智能体。所以三条写入路径（`agent_memory_save`、`agent_journal` 的 `write`、`agent_knowledge_write`）都带上了同一条规则：

> 正文里你自己陈述的事件、决定、计划，用了相对时间就换算成 `YYYY-MM-DD`；引用别人的原话保留原话，另在括号里补日期。

规则写在**工具描述**里（模型写入那一刻唯一会读到的位置），宿主再用 `time.js` 做一次窄口径校验：命中「今天/昨天/下周/上个月…」且正文里没有任何 `2026-10-30`、`10月30日` 这类锚点时，**在工具结果里追加一行提醒**——写入照常成功，因为拒绝写入会丢信息，提醒下一步还能补。`最近`、`目前` 不触发：它们常常就是诚实的精度。

现状统计（改之前，真库）：日志 33 条命中 3 条（9%）、知识库 28 条命中 1 条（4%）、检查点 8 条 0 条——比例不高，但命中的正是"今天又复发一次"这类**跨周还要读的故障记录**。这条规则防的是几周后读错日期，不是检索分数，所以没有评测数字。

### 热度、去重与多样性（2.0.0-beta.4）

三条从 AstrBot-LivingMemory 借来的排序手段，都做成了可关的开关，默认值按"真库上量出来的"定：

| 开关 | 默认 | 作用 | 依据 |
|---|---|---|---|
| `heat` | 0.25 | 被引用/被打开的条目在同分时靠前 | 只改同分，不会越过真正的相关度 |
| `dedupe` | 0 | 高相似度的后续行降权、不删行 | 真库 59 条查询里 top-3 最大 Jaccard **0.19**，0.5/0.75 两个阈值下重复率都是 **0%** |
| `mmr` | 0 | 真 MMR 贪心，用余弦拉开多样性 | 同上：没有重复可去，开了只是多算一次 |

热度是**乘法因子**，`H = 1 + 0.25·(½·min(1, refs/10) + ½·min(1, (opens + exposed/4)/20))`：被引用（正文里出现 `j-xxxx`/`agent-xxxx`）和被人主动打开各算一半，曝光（出现在搜索结果里但没打开）只算四分之一，避免"搜过就算重要"的自激。同分值不移动，是因为真库里大多数查询只有一两条命中，任何强加的热度都会开始改变排序而不是破平局。

打开一条旧笔记还会**把衰减的参照时间往前挪**（`max(at, lastRead)`，上限 `at + 180 天`）：400 天前的笔记被读一次，分数能涨 5 倍以上。上限是防止一次误点让它永久免疫衰减。

面板「回忆」页签的**排序微调**卡片可以改这三个值，保存走 `recall.save`；`memory.index` 的 `settings` 字段回报当前生效值（面板不缓存默认值，避免用旧数字覆盖）。

评测方式：`node eval/dupe-rate.mjs --agent <id>` 算 top-3 的 Jaccard 分布；所有评测脚本都以 `access: false` 构造 `createRecall`，否则测一次就写一次访问计数，第二次跑出来的数字和第一次不一样。

## 已知限制

- **改动插件后必须完全重启 DSH。** 运行中热加载这类 Host 插件会让工具执行上下文失效（所有工具报 `cannot get requested service "sessionProjections" in inactive context`）。这是实测结论，与插件逻辑无关。
- 知识库是全库共享：不做按智能体的隔离，只有贡献者标记（私有日志才是隔离的）。
- 讨论室不自动调度发言，也不限制谁先说；顺序完全由使用方式决定。
- 对话标题来源有两处：live 会话走 `sessionTitle` 服务，已关闭会话读投影缓存；两者都取不到时显示「未命名对话」。
- 面板的视觉细节依赖宿主主题变量 `--dsw-alias-*`，换主题不会破版，但不会跟随自定义设计系统。

## 开发

纯 JavaScript，无构建步骤。两个半片：

- `index.js` — Host：工具、提示词段落、`/api/agent-memory` 路由
- `client.js` — 浏览器：面板与新建对话选择器（手写 ModuleLoader bundle）
- `store.js` — 存储层，不依赖 Cordis，可单独测试
- `rank.js` — 词法打分与衰减（纯函数）
- `graph.js` — 实体抽取与一跳关联扩展
- `rooms.js` — 讨论室存储
- `journal.js` — 私有日志存储
- `handoff.js` — 接力：配置、每会话阶段、检查点文本与导出
- `recall.js` — 召回：索引缓存、词法打分、别名与图扩展、会话来源、语义融合
- `access.js` — 引用/打开/曝光计数（`index/access.json`，热度排序用）
- `embed.js` — 本地 BGE 推理：WordPiece 分词、ONNX 会话、查询指令前缀
- `vectors.js` — 向量库：float32 落盘、按内容 hash 判脏、增量同步、按 420 字分块（取最大余弦）
- `transcripts.js` — 会话原文读取：归属判定、切分消息、文本裁剪、密钥打码
- `zstd-frames.mjs` — 最小 zstd 帧解析（无原生依赖）
- `archive.js` — 归档级别（`weak` / `strong`）的持久记录

设计文档：`docs/handoff-v2.md`（接力 v2）、`docs/sessions-and-workspaces.md`（会话与工作区）、`docs/memory-recall-v2.md`（2.0 记忆召回，已实现并随 2.0.0 冻结）、`docs/embedding-local.md`（本地语义索引，已实现到 2.0.0）、`docs/migrate-1.3-to-2.0.md`（升级与回退步骤）。

node eval/check-cases.mjs      # 用例体检：每条改写查询在纯词法下的真实名次

node eval/recall-paraphrase.mjs # 45 条改写查询：lexical vs hybrid（--title-weight 可扫标题混合）
node eval/recall-grid.mjs      # 顺序轴参数评估（权重 → k → 下限）+ 配对自助法 + 噪声探针（约 10 s）
node eval/semantic-rank.mjs   # 纯语义排名：融合前的检索质量（区分「参数不行」与「检索不行」）
node eval/embed-variants.mjs   # 嵌入输入（整篇 / 前 240 字 / 仅标题）的对照实验
node eval/chunk-variants.mjs   # 分块 A/B：整条 vs 420 字 vs 260 字（临时库，不动真索引）
node eval/title-vs-body.mjs    # 标题加权诊断：查询对标题 / 正文的余弦与两条排序
